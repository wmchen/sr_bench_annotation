## 性能证据与限制

### 10 编辑者 + 20 查看者，30 分钟

使用临时合成数据、本机 loopback HTTP 和本地临时状态盘。
这是 API/存储持续性基准，不代表 30 个真实浏览器或实际内网带宽验收。

| 操作 | 次数 | P50 | P95 | 最大 |
| --- | ---: | ---: | ---: | ---: |
| 草稿保存 | 35,200 | 5.74 ms | 12.09 ms | 236.55 ms |
| 编辑后读取 | 35,200 | 2.91 ms | 5.94 ms | 225.26 ms |
| 查看者读取 | 35,749 | 4.61 ms | 12.26 ms | 261.12 ms |
| 租约续约 | 880 | 5.18 ms | 14.10 ms | 183.37 ms |

复测无失败、无丢失更新。服务 RSS 从约 84.95 MiB 到 95.64 MiB，峰值约 102.89 MiB；
这组数据未显示持续线性增长，但不是长期运行内存保证。
首轮曾出现一次 SQLite 繁忙返回，随后增加有界事务重试并完整复测，
保留 [首轮报告](reports/load-initial.json) 和 [复测报告](reports/load-final.json)。

### 密集标注与推理

- 2500×2400、357 区域：1,000 次整组保存 P95 **110.21 ms**，
  1,000 次读取 P95 **51.37 ms**，无丢失更新。见 [密集数据报告](reports/dense-api.json)。
- PPOCR v6 Medium：1,000 次请求受理 P95 **3.46 ms**，
  服务附加耗时 P95 **15.97 ms**。
- SCRFD：1,000 次请求受理 P95 **3.37 ms**，
  服务附加耗时 P95 **15.76 ms**。

推理测量使用合成 PNG 和实际 GPU 模型。
直接调用基线为同一 worker、同一模型会话内 predict() 的实际计算时间；
总任务耗时扣除实测队列和 predict 时间后，作为包含测试客户端轮询成本的附加耗时上界。
不包含模型加载；排队时间单独报告。见 [推理基准](reports/inference-benchmark.json)。

两套模型在真实图像的临时副本上也通过 CPU/GPU 探测：
文本样本检出 95 个区域并通过选框识别 ID 检查，人脸样本检出 4 个区域。
GPU 预热 profile 记录到 CUDAExecutionProvider；进程正常退出。
这只是阳性流程验证，不是模型准确率评估或整批人工试用。
见 [CPU 报告](reports/models-real-cpu.json)、[GPU 报告](reports/models-real-gpu.json)。
初始验证权重放在临时目录；新增自动下载后，内置模型由服务准备到 cache_dir/models，正式部署应保留该缓存目录。

## 自动下载增量验证

按后续要求新增内置模型自动下载；原有正式试用前置条件继续适用。

- 内置 PPOCR v6 Medium / SCRFD 无需配置文件路径；匹配词表随独立包分发。
- 本地 HTTP 回归覆盖首次下载、进度、下载时保存草稿、短响应、错误 SHA-256、
  损坏缓存修复、自动/手动重试、多组件缓存复用、无 Content-Length、取消和权限撤销。
- 两套模型均从实际 GitHub 发布地址下载到全新临时缓存并通过 CPU 加载；
  随后禁止网络访问再次加载成功，验证缓存复用。
- Chromium / Firefox 验证未缓存模型可选、点击后才下载、字节进度显示及加载期间禁用重复操作。
- 常规测试默认跳过需要外网或真实权重的用例；外网验证可用
  REALISR_TEST_DOWNLOADS=1 显式执行 tests/integration/test_downloads.py。
- 新增代码保持无 Qt 依赖，未引入任何运行时下载执行脚本的入口。
